# 09 운영 및 보안

- 상태: 뼈대 (2026-10-31)
- 이 문서의 목적: V2를 **매일 안전하게 돌리는 절차**를 정해요 — 키, 갱신 일정, 모니터링, 품질, 백업, 라이선스 관리, 비용, 보안.
- 책임 범위: 운영 절차와 기준값, 책임자(사용자/자동), 점검 주기.
- 다루지 않는 것: 검증 규칙 정의 → [05](05-data-architecture.md), 시스템 구조 → [06](06-system-architecture.md), 공급자별 라이선스 판단 → [07](07-data-providers.md)

## 핵심 질문

1. 데이터가 틀리거나 멈추면 누가, 언제, 어떻게 알게 되나?
2. 키가 새거나 공급자 약관이 바뀌면 무엇을 하나?
3. 한 달 비용이 5만 원을 넘지 않게 무엇을 보나?

## 목차

### 1. API 키 관리
- 지금 아는 것 [사실]: V1 키는 GitHub Secrets(`DART_API_KEY`, `ECOS_API_KEY`, 텔레그램)
- 쓸 내용: V2 키 이름 규칙(`V2_` 접두어 [Q-12]), 키 발급·등록은 사용자만, 회수·교체 절차, 브라우저 코드에 키 금지

### 2. 데이터 갱신 주기
- 초안 [기초 분석서 10-3절]: 국장 일봉 평일 14시 이후 1회, 공시 평일 매시, 재무 보고서 시즌 매일·평소 주 1회, 경제지표 매일 07시
- 쓸 내용: 일정표(KST·UTC), 휴장일 처리

### 3. 오류 모니터링
- 재사용: V1 `health.py` 실패 알림 패턴 (워크플로 실패 → 알림)
- 쓸 내용: 알림 채널(V1 텔레그램 봇을 운영 알림으로 쓸지 결정), 알림 기준, 주간 요약

### 4. 데이터 품질 관리
- 쓸 내용: 05의 검증 결과(`check`·`stale`) 처리 절차, 표본 수동 대조 주기(예: 월 1회 대형주 10개 재무·종가), 오류 정정 공지 방법

### 5. 백업 및 복구
- 쓸 내용: 원본 보관 기간, 정규화 저장소 재생성 절차(원본에서 다시 만들기), 공급자 중단 시 마지막 정상본 유지 기간과 화면 안내
- 지금 아는 것 [사실]: 문서·메모는 `docs/backup/`에 백업 (CLAUDE.md 규칙)

### 6. 라이선스 관리
- 쓸 내용: 약관 재확인 주기(예: 분기 1회), 출처 표시 문구 관리, 공급자별 보관·삭제 의무 이행, `license_status` 바뀌면 공개 빌드에서 자동 제외되는지 점검 — 판단 근거는 07

### 7. 운영 비용 관리
- 쓸 내용: 항목별 월 비용 표(데이터·호스팅·저장·도메인), 5만 원 넘기 전 경고 기준
- 결정 필요: 호스팅 [Q-03], 저장소 공개 여부에 따른 Actions 비용 [Q-02] (확인 필요)

### 8. 보안 원칙
- 쓸 내용: 공개 저장소에 개인 설정·비밀값 금지(V1 `paper/watch.json`·`bot.json` 공개 사례 — [03 검토](../business/03-data-migration-risk-review-2026-10-31.md) 1-1절), 의존성 버전 고정(V1 `requirements.txt`는 고정 없음 [사실]), 워크플로 권한 최소화, 로그인·결제 정보 받지 않기(GitHub Pages 금지 사항)
