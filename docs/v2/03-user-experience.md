# 03 사용자 경험

- 상태: 뼈대 (2026-10-31)
- 이 문서의 목적: 사용자가 **어떻게 찾고, 읽고, 더 깊이 들어가는지** 흐름과 원칙을 정해요.
- 책임 범위: 이용 흐름, 시나리오, 검색 경험, 탐색 경험, 기본/상세 구분 규칙, 모바일 UX 원칙.
- 다루지 않는 것: 페이지별 칸 배치 → [04](04-information-architecture.md), 기능의 입력·출력·예외 → [08](08-feature-specification.md)

## 핵심 질문

1. 처음 온 사람이 10초 안에 원하는 회사 정보에 닿는가?
2. 초보자가 숫자를 보고 "이게 무슨 뜻인지" 바로 알 수 있는가?
3. 데이터가 없거나 늦을 때 사용자가 헷갈리지 않는가?

## 목차

### 1. 사용자 이용 흐름
- 기본 흐름 [제안]: 검색 → 기업 페이지 요약 → (탭) 주가·재무·배당·공시 상세 → 원 공시 링크
- 보조 흐름: 홈 → 경제 정보 → 지표 상세
- 쓸 내용: 흐름도(Mermaid), 진입 경로(검색엔진·공유 링크로 기업 페이지에 바로 들어오는 경우 포함)

### 2. 주요 사용자 시나리오
- 쓸 내용: 시나리오 5개 내외, 각 시나리오의 시작·목표·거치는 화면·필요한 데이터
- 후보: ① "삼성전자 최근 실적이 좋아졌나" ② "애플 배당 언제 얼마 주나" ③ "요즘 금리가 오르나" ④ "이 회사 PER이 왜 이렇게 나왔지" (계산 근거 보기) ⑤ "미국 회사 주가가 왜 안 보이지" (데이터 없음 안내)

### 3. 검색 경험
- 지금 아는 것 [사실]: V1 너그러운 검색(초성·오타·별명) 재사용 가능 ([기초 분석서](01-architecture-design.md) 3-1절)
- 쓸 내용: 검색 결과 한 줄에 무엇을 보여 줄지(시장·종류·제공 범위 배지), 결과 없음, 동명 회사, 상장폐지
- 필요한 결정: 검색 범위(종목만 / 경제지표도) [제안: 둘 다]

### 4. 정보 탐색 경험
- 쓸 내용: 페이지 사이 이동 규칙(뒤로 가기, 탭 유지), 국장/미장 전환 방식([제안] 전역 탭 없이 결과·페이지 안에서), 최근 본 회사
- 필요한 결정: '내 목록' 범위 [미결정 Q-16]

### 5. 기본 정보와 상세 정보의 구분
- [결정 D-09] 기본은 쉽게, 상세는 깊게
- 쓸 내용 [제안 규칙]: ① 요약 칸은 숫자 4~5개 + 한 줄 설명 ② 상세는 펼치기·탭 ③ 모든 지표 옆 "?"로 쉬운 설명(V1 용어집 재사용) ④ 계산 지표는 "계산식 보기"
- 출처·기준일 표시 규칙 [결정 D-08]: 숫자 칸 아래 작은 글씨 `출처 · 기준일`, 늦은 데이터는 색·문구로 구분 (메타 필드 정의는 [05](05-data-architecture.md))

### 6. 모바일 UX 원칙
- 지금 아는 것 [사실, V1 규칙]: 버튼 눌러도 화면 위치 그대로, 바 sticky 금지, 디자인 토큰(`site/style.css`), Pretendard 글꼴
- 쓸 내용: 터치 크기, 글자 크기, 다크 모드, 동작 줄이기 설정 존중, 표는 가로 스크롤 대신 카드화 기준
- 데이터 없음·지연·확인 중 상태 문구 3종 (빈칸 금지)
