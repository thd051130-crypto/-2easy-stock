# 05 데이터 아키텍처

- 상태: 뼈대 + 초안 연결 (2026-10-31)
- 이 문서의 목적: 공급자와 상관없는 **공통 데이터 모델**과 데이터가 수집→변환→검증→저장→갱신되는 규칙, 출처·기준일 관리 규칙을 정해요.
- 책임 범위: 데이터 유형, 공통 스키마, 변환 규칙(통화·회계기간·수정주가·배당 날짜), 검증 규칙, 저장 단위, 갱신 주기 원칙, 메타 필드.
- 다루지 않는 것: 공급자별 원본 형식·비용·라이선스 → [07](07-data-providers.md) (**라이선스 판단은 07만**), 코드 모듈·배포 → [06](06-system-architecture.md), 운영 알림 절차 → [09](09-operations-security.md)
- 초안: [기초 분석서](01-architecture-design.md) 6장(Adapter 설계)·7장(공통 스키마)을 이 문서가 이어받아요. 세부를 쓸 때 거기서 옮기고 분석서엔 링크만 남겨요.

## 핵심 질문

1. 공급자가 바뀌어도 화면과 서비스 로직이 그대로이려면 어떤 공통 형식이어야 하나?
2. 통화·회계기간·수정주가·배당 날짜 차이를 어디서 어떻게 흡수하나?
3. 틀린 숫자를 정상처럼 보여 주지 않으려면 어떤 검증이 필요한가?

## 목차

### 1. 데이터 유형
- 주가(일봉), 기업 기본정보·상장 정보, 재무제표, 배당·기업행사(분할 등), 경제지표·환율, 공시
- 쓸 내용: 유형별 시장(국장/미장) × 제공 여부 표 (공급자 판단은 07 결과만 인용)

### 2. 공통 데이터 모델
- 초안 [기초 분석서 7장]: `Instrument`, `Company`, `PriceBar`, `CorporateAction`, `DividendEvent`, `FinancialStatementItem`, `MacroSeries/MacroObservation`, `FxRate`, `Filing`, `DerivedMetric`
- 쓸 내용: 엔터티별 필드·형식·필수 여부, 식별자 규칙(`KR:005930`, `KR-DART:…`, `US-CIK:…`), 스키마 버전 정책
- 원칙 [제안]: yfinance DataFrame 모양을 기준으로 삼지 않음 (통화·기간·날짜·출처를 못 담음 — 기초 분석서 6-1절)

### 3. 데이터 수집
- 쓸 내용: 수집 요청 단위(영역 × 시장 × 기간), 원본 보관 원칙(비공개, 공개 저장소 커밋 금지 [제안])
- 공급자 호출 방식 상세는 06(Adapter)과 07(공급자)

### 4. 데이터 변환
- 쓸 내용 [기초 분석서 6-2·6-3절 초안 있음]:
  - 통화: 모든 금액에 ISO 통화, 비율은 같은 통화일 때만, 환산 시 환율 출처
  - 회계기간: `fiscal_year`·`fiscal_period`·`period_start`·`period_end`, 4분기 = 연간 − 1~3분기, 누적 → 3개월
  - 수정주가: 원가격 + 기업행사 저장, 수정가격은 계산, `adjustment` 필드
  - 배당: 선언·배당락·기준·지급일 분리, 모르는 날짜는 추정하지 않음
  - 회계 기준: `accounting_standard` (K-IFRS·US-GAAP 등), 표준 계정 키 매핑표

### 5. 데이터 검증
- 쓸 내용: 규칙 목록과 결과 상태
- 초안: 형식(스키마), 범위(0·음수, 고가≥저가), 연속성(빠진 거래일), 이상값(±30% vs 분할 공시), 회계 등식(자산=부채+자본), 분기 합≈연간, 공급자 간 대조
- 결과: `data_status` = `ok`·`partial`·`stale`·`check`·`unavailable`. **값을 고치지 않고 표시만**

### 6. 데이터 저장
- 쓸 내용: 저장 계층 3개 — 원본(비공개) / 정규화(엔터티별 파일 → 나중에 테이블) / 공개 빌드(페이지 단위 JSON)
- 저장 위치·용량·보관 기간은 06·09

### 7. 데이터 갱신
- 쓸 내용: 유형별 갱신 원칙(일봉 하루 1회, 재무 보고서 시즌 매일, 경제지표 매일, 공시 매시), `expected_by`로 지연 판정
- 실제 일정표는 09

### 8. 출처 및 기준일 관리
- 초안 메타 블록 [기초 분석서 7장]: `source`, `as_of`, `collected_at`, `published_at`, `currency`, `adjustment`, `license_status`, `attribution`, `data_status`, `schema_version`
- 원칙: 공개 빌드는 `license_status`가 `public_attribution`·`licensed_display`인 것만 — 값 정의는 여기, **어느 공급자가 어느 값인지는 07**
- 화면 표시 규칙은 03
