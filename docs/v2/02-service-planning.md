## 2. 사용자의 불편과 요구 [가설]

| 불편 | 요구 | 맡는 영역 |
|---|---|---|
| 재무 숫자가 사이트마다 다르고 기준이 안 보임 | 원천과 같은 숫자, 기준(연결/별도·회계기간) 표시 | 재무제표·재무지표 |
| 지표 이름은 아는데 뜻과 계산법을 모름 | 쉬운 설명 + 계산식 | 재무지표 |
| 배당 날짜(배당락·기준·지급)가 섞여서 헷갈림 | 날짜별 구분 | 배당 |
| 국내·미국 회사를 다른 사이트에서 따로 봐야 함 | 같은 틀로 한곳에서 | 통합 검색·기업 정보 |
| 금리·환율이 내 투자와 어떻게 이어지는지 모름 | 핵심 지표와 짧은 설명 | 경제지표 |
| 숫자가 언제 기준인지 모름 | 기준일·갱신 시각 | 전 영역 |

이 표의 불편이 실제로 있는지, 기존 서비스가 이미 풀고 있는지는 **확인 필요**예요 (5장 경쟁 조사).

## 4. 서비스 차별점 [가설]

경쟁 서비스와 비교한 우위는 **근거 없이 단정하지 않아요.** 아래는 후보예요. 검증 전에는 마케팅 문구로 쓰지 않아요.

| 후보 | 왜 후보인가 | 실현 가능성 | 검증 방법 |
|---|---|---|---|
| ① 계산 근거 공개 ("이 숫자가 왜 이렇게 나왔나") | 지표마다 입력값·기준일·공식을 보여 줌 | 높음 — 공통 스키마의 `DerivedMetric.inputs` ([기초 분석서](01-architecture-design.md) 7장) | 경쟁 서비스에 같은 기능이 있는지 조사, 상세 보기 열람률 |
| ② 출처·기준일 칸마다 표시 | 투명성 가치 | 높음 — 메타 블록 | 경쟁 조사, 사용자 반응 |
| ③ 국내·미국 기업을 같은 틀로 | 편의성 가치 | 재무는 높음, **주가는 미장 라이선스에 달림** | 경쟁 조사 |
| ④ 용어를 없애지 않고 설명하는 쉬운 한국어 | 이해도 가치, V1 용어집 자산 | 높음 | 사용자 피드백 |
| ⑤ 배당 날짜 4종 구분 | 혼동이 잦은 지점 [가설] | 중간 — 원천 확인 필요 | 경쟁 조사 |

- 시세 속도·실시간·차트 도구는 차별점으로 삼지 않아요. 기존 증권 앱이 더 잘해요 [01 수익화 진단 A-6, 추정].
- AI로 쉽게 따라 할 수 있는 요약 문장은 차별점으로 치지 않아요 [01 수익화 진단].

### 경쟁 서비스 조사 항목 (할 일)

| 대상 | 조사 항목 |
|---|---|
| 네이버페이 증권, 토스증권, 증권사 MTS, 아이투자, 인베스팅닷컴 등 | 무료 범위, 재무 깊이(분기·연결/별도), 계산 근거 공개 여부, 출처·기준일 표시, 배당 날짜 구분, 미국 기업 지원, 초보자 설명, 광고 양 |

## 5. 핵심 정보 제공 전략

1. **원천 우선** [결정 D-07·D-14]: 공시·공공 통계 원천을 쓰고, 2차 가공 데이터는 라이선스가 확인될 때만 써요.
2. **계산은 직접, 공식은 공개**: PER·PBR·ROE·배당수익률 등은 원천 값으로 직접 계산하고, 계산식을 보여 줘요.
3. **해석 대신 설명**: "좋다/나쁘다", "싸다/비싸다" 대신 "무엇을 뜻하는지"와 "과거와 비교하면 어떤지"를 보여 줘요. 같은 업종 평균 비교를 넣을지는 [미결정 Q-23]이에요 (평가로 읽힐 수 있음).
4. **없으면 비운다**: 데이터가 없거나 확인 중이면 칸을 비우고 이유를 써요. 추정해서 채우지 않아요.
5. **우선순위** [제안]: 재무·배당(국내외 원천 확보 가능) → 경제지표 → 주가(라이선스 확인 후). 실행 순서는 [10](10-development-roadmap.md).

## 6. 기본 보기와 상세 보기 정책

[결정 D-15] 기본 정보와 상세 정보를 나눠요. **전문 용어는 없애지 않고 설명해요.**

| 구분 | 담는 것 | 규칙 [제안] |
|---|---|---|
| **기본 보기** | 핵심 수치, 주요 그래프, 쉬운 용어 설명, 주요 변화 요약 | 화면 하나 분량. 수치 4~6개. 용어 옆 "?" 설명. 변화 요약은 **사실 문장만**("영업이익이 전년보다 12% 늘었어요"), 평가 단어 금지 |
| **상세 보기** | 연간·분기 재무제표, 과거 데이터, 상세 지표, 계산 기준, 데이터 출처 | 펼치기·탭. 표 그대로, 단위·통화·회계기준·연결/별도 표시, 원문 링크, 갱신 시각 |

- 두 보기는 **같은 데이터**를 써요. 기본 보기 숫자는 상세 보기에서 반드시 찾을 수 있어야 해요.
- 화면 배치·전환 방식은 [03](03-user-experience.md)·[04](04-information-architecture.md)에서 정해요.

## 7. 수익화 방향

[결정 D-18] 초기에는 **무료 정보 제공이 중심**이에요. **유료 기능을 미리 개발하지 않아요.** 실제 수요와 운영비를 확인한 뒤 결정해요.

검토할 모델(광고·상세 데이터 프리미엄·기업 비교·고급 검색/필터·데이터 리포트 + 관심종목·알림·B2B)의 고객·지불 이유·데이터 권리·비용 평가와 커뮤니티 검토는 **[11 수익화 모델과 커뮤니티](11-monetization-and-community.md)**에 모아 뒀어요. 현실적인 후보는 광고(트래픽 이후)와 공공 원천 기반 비교·필터·알림 구독(조건부)이에요 [제안].

**유료화 검토 시작 조건** [제안, [미결정 Q-15]]:
1. 01 성공 기준의 출시 후 지표(재방문 등)가 목표 문턱을 넘는다.
2. 해당 데이터의 상업·유료 이용이 공급자 원문이나 서면으로 확인된다.
3. 법률 확인(유사투자자문업 해당 여부)이 끝난다 [Q-20].
4. 월 운영비(데이터·호스팅)와 예상 수입이 비교된다 ([09](09-operations-security.md)).

설계상 미리 할 것은 **유료 기능 자리를 비워 두는 것이 아니라**, 데이터 메타에 `license_status`를 남겨 나중에 "유료 표시 가능" 여부를 가릴 수 있게 하는 것뿐이에요 ([05](05-data-architecture.md)).

## 8. 운영 원칙

| 원칙 | 내용 |
|---|---|
| 판단을 대신하지 않음 [D-02] | 화면·문구에 "매수·매도·추천·유망·목표가·저평가·고평가" 같은 말을 쓰지 않아요 (금지어 목록은 [09](09-operations-security.md)에서 관리) |
| 출처 없는 숫자 금지 [D-08] | 출처·기준일 없는 값은 공개 빌드에서 빠져요 |
| 라이선스 미확인 데이터 금지 [D-07] | `license_status`가 `unknown`이면 공개하지 않아요 |
| 오류는 숨기지 않음 | 틀린 값을 발견하면 정정하고 정정 사실을 기록해요 (절차는 09) |
| 지연은 정상 기준으로 안내 | 국장 공공 시세처럼 원래 하루 늦은 데이터는 "오류"가 아니라 "기준일"로 표시해요 |
| 기능 추가는 수요가 있을 때 | 새 기능은 핵심 영역과 성공 기준에 맞는지 먼저 확인해요 |
